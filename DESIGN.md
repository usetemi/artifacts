# Design

How Artifacts is built: architecture, Ash resources, authentication, the
page runtime, the MCP and HTTP interfaces, and deployment. `DOMAIN.md` owns
the language and the rules; this document names how each rule is carried
out and does not restate it. `README.md` is the short user-facing summary.

## Architecture

```
 Claude Code / Codex / Agent ── MCP + HTTP (bearer key) ──┐
                                                           ▼
 browser ── usetemi.art: sign-in, lists, settings, chrome ─► host (Phoenix + Ash) ── Postgres
    └─ iframe ── usetemicontent.art: page HTML + runtime.js ─►  │ Channels, PubSub, Presence
```

One Elixir release is the host. Ash resources hold the domain; Phoenix
serves the web app, the page origin, the channel socket, the MCP endpoint,
and the HTTP API from the same endpoint. Postgres is the only store. Every
artifact has one channel topic, `artifact:<id>`, which carries state ops,
presence, broadcast, and version events. There is no broker and no sync
service.

| Library | Role |
| --- | --- |
| `ash`, `ash_postgres` | Resources, actions, policies, Postgres data layer and migrations. |
| `ash_authentication`, `ash_authentication_phoenix` | Google sign-in for Users; API-key sign-in for Harnesses and Agents. |
| `ash_phoenix` | Forms and LiveView integration for the web app. |
| `ash_ai` | The MCP server: resource actions exposed as MCP tools. |
| `ash_json_api` | The HTTP API, generated from the same actions. |
| `usage_rules` | Syncs each dependency's usage rules into `server/AGENTS.md`. |

## Ash domains and resources

Two Ash domains, `Artifacts.Accounts` and `Artifacts.Publishing`.
Organization scoping is `belongs_to :organization` plus policies, not Ash
multitenancy (see [Rejected alternatives](#rejected-alternatives)).

### `Artifacts.Accounts`

| Resource | Holds | Notes |
| --- | --- | --- |
| `User` | email, name, `personal_organization_id` | Google strategy. `register_with_google` is an upsert on email. |
| `Token` | AshAuthentication session tokens | Generated by AshAuthentication. |
| `Organization` | name | |
| `Membership` | `user_id`, `organization_id` | Unique per pair. No role. |
| `Harness` | `user_id`, name, key hash, `expires_at`, `revoked_at` | The User's API-key resource: a Harness is one named key. |
| `Agent` | `organization_id`, name | Its own AshAuthentication resource with an API-key strategy and no token resource — it issues no tokens. |
| `AgentKey` | `agent_id`, name, key hash, `expires_at`, `revoked_at` | An Agent's keys. |

### `Artifacts.Publishing`

| Resource | Holds | Notes |
| --- | --- | --- |
| `Artifact` | 22-char URL-safe random id, `organization_id`, title, `current_version`, `archived_at` | The aggregate root; every content action runs on it. |
| `Version` | `artifact_id`, number, html, actor | Create only. Primary key `(artifact_id, number)`. |
| `StateEntry` | `artifact_id`, path, value, actor, `updated_at` | One row per leaf path; see [State](#state). |
| `Submission` | `bigserial` id, `artifact_id`, version, state snapshot, payload, actor | Create only. The id is the wait cursor. |
| `Event` | `bigserial` id, `artifact_id`, kind, actor, data, `inserted_at` | Create only. The id is the History order. |

The Artifact id is a plain string attribute rather than an Ash builtin id
type, generated by `Base.url_encode64(:crypto.strong_rand_bytes(16),
padding: false)`. `StateEntry.value` and `Submission.payload` are
`Artifacts.Type.JSONValue`, a pass-through Ash type over Postgres's `map`
storage, so a non-map write is rejected the same way the column always
has. `Artifacts.Repo` declares `min_pg_version` 17, the Postgres version
this runs on.

Actor columns are the same on `Version`, `StateEntry`, `Submission`, and
`Event`: nullable `user_id`, `harness_id`, and `agent_id`. A User acting
through the browser sets `user_id`; a Harness sets `user_id` and
`harness_id`; an Agent sets `agent_id`. A check constraint requires exactly
one of `user_id` and `agent_id`, and `harness_id` only with `user_id`.

`Version`, `Submission`, and `Event` have no update or destroy actions,
and a `BEFORE UPDATE OR DELETE` trigger on each table raises: no
application path updates or deletes a record, and the trigger refuses
the statement even if one tried to. `Artifact` has no destroy action.

## Authentication and actors

Three credentials, two actor types. Policies only ever see a `User` or an
`Agent`.

| Credential | Presented by | Resolves to |
| --- | --- | --- |
| Session cookie from Google sign-in | Browser on usetemi.art | `User` |
| Harness key (`Authorization: Bearer arth_…`) | Claude Code or Codex over MCP or HTTP | `User`, with the `Harness` in `user.__metadata__.api_key` |
| Agent key (`Authorization: Bearer arta_…`) | A coworker agent over MCP or HTTP | `Agent` |

Keys are generated by AshAuthentication's `GenerateApiKey` change with
prefix `arth` for a Harness and `arta` for an Agent —
`arth_<token>_<checksum>` and `arta_<token>_<checksum>` — stored as a
hash and shown once at creation. The bearer plug routes by prefix to the
User or Agent API-key strategy. A plug after it copies the Harness id
into the Ash context so actions can record it; that is the only place
the Harness enters the actor columns.

**Sign-up.** `register_with_google` rejects an email that is unverified
or whose domain is not in `SIGNUP_EMAIL_DOMAINS` (empty means any), so no
User row is written. On success an `after_action` hook, in the same
transaction, creates the Personal Organization and its Membership and
sets `personal_organization_id` when the User has none, so a repeat
sign-in changes nothing. Matching is on email alone, not a verified
provider identity, so two different Google accounts that ever share an
email — a deleted-and-reused address, a Workspace alias repoint — upsert
into the same row; accepted while the Instance is Google-only and
domain-allowlisted.

**Membership invariant.** `Membership.destroy` (remove or leave) locks the
organization row and refuses when it is the last Membership. Adding a
member looks up an existing User by email and fails when there is none.

**Policies.** One rule covers every `Artifacts.Publishing` action and the
Organization-scoped Accounts actions: a `User` passes when
`exists(organization.memberships, user_id == ^actor(:id))`, an `Agent`
when `organization_id == ^actor(:organization_id)`. `Harness` actions
pass only for their own User. Actions that manage access (Membership
create and destroy, Agent create, Harness and AgentKey create and revoke)
also `forbid_if AshAuthentication.Checks.UsingApiKey` and forbid Agent
actors, so only a browser-signed-in User manages access. Reads by id load the record and filter by
the rule, so a non-member gets not-found, never forbidden. `Version`,
`StateEntry`, `Submission`, and `Event` each forbid any caller of their
own create action other than the `Artifact` action that creates them;
that action's own `after_action` creates them with `authorize?: false`,
since the `Artifact` action already established the actor may act on it.

**Actor reference.** Every wire mention of who did something — `by` on
`state:ops` and `version`, `from` on `broadcast` — is `{type: "user" |
"agent", id, name, harness}`. `harness` is the Harness's name when a User
acted through one, else `null`; an Agent's reference carries `harness:
null` too. `Artifacts.Publishing.Actor.ref/2` builds it.

## Content changes

Every content change is one action on `Artifact` that writes the change
and its `Event` in one transaction and then broadcasts on
`artifact:<id>`. The `Event.data` holds a pointer, not a copy:

| Action | Writes | `Event.kind` | `Event.data` |
| --- | --- | --- | --- |
| `publish` | a `Version`, bumps `current_version` | `version_published` | `{number}` |
| `change_state` | `StateEntry` upserts and deletes | `state_changed` | the ops list |
| `submit` | a `Submission` | `submission_made` | `{submission_id}` |

`create` is `publish` on a new Artifact: it inserts the Artifact with
`current_version` 0 in the target Organization (named, else the actor's
Personal Organization; an Agent's own), then publishes version 1.

`publish` takes an optional `if_version`; it locks the Artifact row and
returns a conflict error when `current_version` differs. Self-Publish
always sends it.

`rename`, `archive`, and `unarchive` update the Artifact and write no
Event. Every content action validates `archived_at` is nil and fails
with an `archived` error otherwise.

Caps, each a validation with a visible error: 16 MiB per Version, 256 KiB
per state value, 10,000 state rows and 10,000 submissions per Artifact.

Every failure resolves to one of a small set of stable codes —
`conflict`, `archived`, `not_found`, `forbidden`, `quota`, `invalid` —
through one module, `Artifacts.Publishing.Errors.to_code/1`. The
channel's error replies, the Page API's rejections, and the MCP and HTTP
error responses all read through it; nothing maps an error a second way.

### State

State is a JSON object assembled from rows, one row per leaf at a dotted
path. `set("a.b", 1)` upserts `a.b`; setting a path replaces every row at
or below it with the leaves of the new value, so the document never holds
both `a` and `a.b`. `delete("a")` removes `a` and `a.*`. Arrays are one
leaf; to edit elements independently, key them (`items.<id>`). `null`
means absence: a top-level `{op: "set", value: null}` normalizes to a
`delete` before it reaches storage. A path is at most 1000 bytes, with no
empty segment (`a..b`, `.a`) and no whitespace. Ops in one `change_state`
apply in one transaction; across changes the last write to a path wins.

### History

`Artifact.history` reads the artifact's Events in id order, paged by an
`after` cursor, and loads what each points at: the Version (with or
without HTML, by flag), the Submission, or the ops inline. Presence and
broadcast never reach the database.

## Page origin and runtime

usetemi.art serves the web app, its `/auth` routes, the HTTP API, and the
MCP endpoint; usetemicontent.art serves only the page route and the page
socket, setting no cookies and reading none. A runtime plug compares the
request host against the configured app and content hosts and assigns
which role applies; each pipeline requires its own role and 404s on a
mismatch, so the split holds without a compile-time router host scope. In
development the two hosts are `localhost:4000` and `127.0.0.1:4000`, the
same port under different names.

**Page token.** The chrome LiveView mints a `Phoenix.Token` carrying the
artifact id and the viewing User's id, valid for 10 minutes. The iframe's
`src` is `https://usetemicontent.art/a/<id>/page?t=<token>`. The page
route verifies the token, reloads the User, re-checks against the
policy, and returns the current Version's HTML with
`<script>window.__ARTIFACT__ = {id, version, token, socketUrl,
appOrigin, viewer}</script>` and the runtime `<script
src=".../runtime.js">` injected right after `<head>`, JSON-encoded with
`</` escaped. Stored HTML is never modified. The token's 10-minute
lifetime bounds any leak; responses also set `Referrer-Policy:
no-referrer` and `Cache-Control: no-store`, and the `t` parameter is
filtered from request logs. Responses carry a CSP allowing scripts from
this origin and the common CDNs, connections to the socket host only,
images from anywhere, and `frame-ancestors` naming the app origin, so
only the chrome can embed the page. The iframe is `sandbox`ed with
scripts, same-origin, forms, modals, popups, and downloads allowed, but
not top navigation, so a page cannot navigate the chrome's tab.

An archived Artifact's chrome shows its title and archive status with an
Unarchive control and no iframe; its Versions, State, and History are
read through MCP and the HTTP API.

**Socket.** The page socket's `check_origin` is the content origin; the
LiveView socket's is the app origin. The runtime connects to the page
socket with the token as a connect param; the socket assigns the actor,
and joining `artifact:<id>` requires the token's artifact id. When a
connect is refused, or the token is more than nine minutes old before a
reconnect, the runtime posts `{type: "artifact:token-request", id}` to
the chrome's window at the app origin. The chrome's hook accepts it only
from the iframe's own window at the content origin, asks the LiveView
for a fresh token over `pushEvent`, and posts `{type: "artifact:token",
token}` back to the iframe at the content origin; the runtime accepts
that reply only from `window.parent` at the app origin.

A new Version reaches the chrome over the same PubSub topic the channel
publishes on. The chrome mints a fresh token and rewrites the iframe's
`src` rather than reloading the frame, which only works same-origin; the
channel still pushes `version` to pages, for a page's own Self-Publish
callers. State survives because it is in Postgres. The actor recorded
for a Submit note is read from the LiveView's own session, never from
the iframe's `contentWindow`, which also only works same-origin.

### Channel protocol

The join reply carries `{version, state}`, `state` being the flat map of
rows by dotted path (`Publishing.get_leaves`, not `get_state`'s nested
object); Phoenix
Presence sends the list right after, keyed by the Viewer's id with
`{name, meta}`, `meta` starting empty. An archived artifact refuses the
join.

| Direction | Event | Payload |
| --- | --- | --- |
| page → host | `state:ops` | `[{op: "set", path, value} \| {op: "delete", path}]`; reply after commit |
| host → pages | `state:ops` | the same ops plus `by`, to every subscriber, the writer included |
| page → host | `presence:update` | meta (JSON object, at most 4 KiB encoded) to merge into this viewer's presence; oversized meta is refused with `{error: "invalid"}` |
| page → host | `broadcast` | `{topic, data}`; re-emitted to the other pages with `from` |
| page → host | `submit` | `{payload}`; reply `{id}` |
| page → host | `publish` | `{html, if_version}`; reply `{version}` or `{error: "conflict"}` |
| host → pages | `version` | `{version, by}` on every publish |

There is no `submission` push to pages: the chrome learns of one over
the same PubSub topic directly, not through this channel.

Channel writes call the same `Artifact` actions as MCP and HTTP, with the
token's actor.

### Page API

`runtime.js` defines `window.artifact`, available synchronously; its
connection opens asynchronously, so pages await `artifact.ready`.

```js
await artifact.ready;
artifact.id; artifact.version;
artifact.viewer;                       // {id, name}: the signed-in User

artifact.state.get("cards.c1");
await artifact.state.set("cards.c1.column", "done");
await artifact.state.delete("cards.c1");
const stop = artifact.state.subscribe((state) => render(state));

artifact.presence.track({cursor: [120, 44]});
artifact.presence.onChange((viewers) => renderPeers(viewers));
artifact.presence.list();              // [{id, name, ...meta}]

artifact.broadcast("pointer", {x, y});
artifact.on("pointer", (data, from) => flash(data, from));

await artifact.submit({choice: "B"});
await artifact.publish(html);          // rejects {code: "conflict"}
```

`state.set` applies locally at once and resolves on commit. `subscribe`
fires once, synchronously, if already synced, and then per change,
coalesced per animation frame. Every write rejects with one of the
stable codes named in [Content changes](#content-changes), or
`unavailable`, which the runtime adds on its own for a write attempted
while disconnected. `from` on `on` carries the same actor shape as `by`
elsewhere on the wire: `{type, id, name, harness}`. The runtime never
touches the DOM. The chrome's own Submit control, outside the page, has
a multi-line note field and calls `Artifacts.Publishing.submit` directly
with `{"note" => note}` when it is filled and no payload otherwise, so
every page can be handed back, with or without words.

## Agent interfaces

### MCP

`AshAi` exposes the tools below at `https://usetemi.art/mcp` (streamable
HTTP), behind the bearer plug. Each tool is an `Artifact` or
`Organization` action, so MCP enforces the same policies as the web. The
endpoint keeps its default `allowed_origins`: only `localhost`,
`127.0.0.1`, and requests with no `Origin` header pass, since Claude Code
and Codex send none; a browser-based MCP client is out of scope. Its
`mcp_name` is set explicitly rather than left to derive. Its `initialize`
response carries short `instructions`, under 2 KB: the loop, the error
codes, and a pointer to `get_guide`.

| Tool | Action |
| --- | --- |
| `get_guide` | The agent guide, `skills/artifacts/SKILL.md`. |
| `list_organizations` | Organizations the actor can act in. |
| `list_artifacts` | Open artifacts in one Organization. |
| `get_artifact` | A map of metadata and, optionally, a Version's HTML. |
| `publish_artifact` | Create, or publish a new Version (`if_version`). |
| `get_state` / `change_state` | Reduced State; apply ops. |
| `submit` | Submit with an optional payload. |
| `wait` | Submissions after `since`; see below. |
| `history` | One page of the History after a cursor. |
| `rename_artifact` / `archive_artifact` / `unarchive_artifact` | Metadata and closeout. |

**`wait`** is a generic action: `wait(artifact_id, since, timeout)`. It
subscribes to the artifact's topic, reads Submissions with `id > since`,
and returns them at once or blocks until one arrives or `timeout`
passes, then returns an empty list. `since` omitted means "after the
latest submission now". `timeout` is in milliseconds, defaults to 40000,
and is capped there: a call that lands on a stopped Machine also waits
out its roughly ten-second start, and the sum stays under both
harnesses' 60-second default MCP tool timeouts. The agent
calls again with the last id it saw.

Connecting a harness:

```
claude mcp add --transport http artifacts https://usetemi.art/mcp \
  --header "Authorization: Bearer arth_…"
```

```toml
# ~/.codex/config.toml
[mcp_servers.artifacts]
url = "https://usetemi.art/mcp"
bearer_token_env_var = "ARTIFACTS_KEY"
```

### HTTP API

`AshJsonApi` routes under `/api` expose the same actions for anything
that is not an MCP client, authenticated by the same bearer keys. `wait`
and `history` are ordinary generic-action routes on `Artifact`, blocking
an HTTP call the same way they block an MCP one — neither streams nor
long-polls. `Version` is not its own JSON:API resource type; its HTML is
reached only through `GET /api/artifacts/:id/versions/:n.html`, a plain
route declared ahead of the `/api` forward, and through `get_artifact`'s
own include-HTML argument.

### Skill

`skills/artifacts/SKILL.md` teaches the loop over MCP: when a page beats
text, how to write one against `window.artifact`, `publish_artifact`,
`wait` in a loop, act on the Submission, republish, and read `history`.
The server embeds it at build time, so a connected harness needs no
install: `get_guide` returns it whole, and the `initialize` instructions
carry a short version that points there. Copying `skills/artifacts/`
into a harness's skills directory remains an option.

## Web app

LiveView on usetemi.art, behind Google sign-in:

- **Artifacts**: the open Artifacts of the selected Organization, with an
  Organization switcher; archived ones behind a filter.
- **Artifact page** (`/a/:id`): the chrome (title, Version, Presence,
  Submit, rename, archive) around the page iframe. The chrome renders
  Presence from the same topic without tracking itself as a Viewer.
- **Settings**: create an Organization; add a member by email, remove a
  member, leave; create an Agent and issue or revoke its keys; create or
  revoke your own Harnesses. A new key is shown once.

Sign-in and settings are styled with hand-written CSS, plus a small
`AuthOverrides` module for `ash_authentication_phoenix`'s components;
neither Tailwind nor daisyUI is a dependency.

## Repository layout

```
server/    Phoenix + Ash application, including runtime.js
skills/    artifacts/SKILL.md
examples/  complete pages to start from
deploy/    docker-compose.yml, fly/fly.toml, deploy docs
.github/   CI and the release, whose only artifact is a container image
AGENTS.md CLAUDE.md DOMAIN.md DESIGN.md README.md LICENSE
```

The root `AGENTS.md` loads `DOMAIN.md` and `DESIGN.md`; `CLAUDE.md`
imports it. `server/AGENTS.md` holds the Phoenix guidelines and the
usage-rules block that `mix usage_rules.sync` writes from the
`usage_rules` config in `server/mix.exs`: Phoenix and `usage_rules`
inline, Ash and its extensions as links into `deps/`. `.formatter.exs`
adds `Spark.Formatter` and each Ash extension to `import_deps`, so their
`attributes do ... end` blocks format consistently.

## Deployment

**Fly.io** (`deploy/fly/fly.toml`): one Machine that stops when nothing
is connected and starts on the next request, serving both hostnames, in
the same region as a Fly Managed Postgres cluster. `DATABASE_URL` is set
from the cluster's direct-host credentials, not the pooled PgBouncer URL
`fly mpg attach` would default to: the Machine keeps its own Ecto pool
(`POOL_SIZE`, default 10), so no pooler sits in front of it.
`ECTO_IPV6=true` is set, since Fly's private network is IPv6-only.
Migrations run as the `release_command`, against the same
`DATABASE_URL`. Both hostnames get certificates with `fly certs add`.
MPG's backups hold the record. An open page's socket or a running `wait`
keeps the Machine up; after a stop, pages reconnect and rejoin with a
fresh snapshot, and `wait` resumes from its cursor.

**Docker Compose** (`deploy/docker-compose.yml`): the image plus a
Postgres container; local development, tests, and self-hosting. Two
hostnames are needed locally too; `localhost` and `127.0.0.1` serve as
app and content hosts.

Configuration is environment variables: `DATABASE_URL`,
`SECRET_KEY_BASE`, `TOKEN_SIGNING_SECRET`, `APP_HOST`, `CONTENT_HOST`,
`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `GOOGLE_REDIRECT_URI`,
`SIGNUP_EMAIL_DOMAINS`, `PORT`, `POOL_SIZE`, `DATABASE_SSL`,
`ECTO_IPV6`, `PHX_SCHEME`, `PHX_URL_PORT`. `GOOGLE_REDIRECT_URI` defaults
to the app origin plus `/auth/user/google/callback`; whichever value is
configured must match Google Cloud Console's registered redirect URI
character for character. `DATABASE_SSL` turns on TLS with the OS trust
store; off by default, since MPG's traffic already travels Fly's private
network. `PHX_SCHEME` and `PHX_URL_PORT` override the derived
`https`/`443` for a plain-`http` deployment — Docker Compose's
`http://localhost:4000` and `http://127.0.0.1:4000` — and feed the app
origin used above, the `check_origin` values, the iframe's `src`, and
the CSP's `frame-ancestors`.

## Limitations

- **Content origin is shared across artifacts.** Every page runs on one
  content origin, so pages share its localStorage and can read what
  another page stored there. Per-artifact subdomains would separate them.
- **A page can exfiltrate what its viewer can see of its own artifact.**
  The CSP limits connections but allows images from anywhere.
- **Single node.** PubSub fan-out is in-process; a second node needs a
  shared PubSub adapter.
- **Nothing is deleted.** The database only grows.

## Roadmap

Deferred with the shape it will take when built. None of it is in the
MVP.

- **Attachments.** A Viewer hands the page or the agent a file, such as
  a reference sketch of the chart they want. Adds an Attachment on a
  Submission, file storage, and a way to fetch it from the runtime and
  MCP.
- **Element References.** A person points at part of the page, as in
  "make this smaller" with the figure selected. The chrome gets a pick
  mode that captures a selector and a short HTML snippet into the
  Submission payload; the skill teaches the agent to read them.
- **An in-browser message panel.** Conversation beside the page, with
  the agent replying in it. Considered for the MVP and deferred: the
  conversation stays in the harness or the chat tool with the link,
  and the Submit note carries what a person wants to say to the page's
  agent.

## Rejected alternatives

- **Ash multitenancy for Organizations.** Artifacts are opened by
  unguessable id before their Organization is known (links, MCP calls
  that name none), so every such read would bypass the tenant and re-check
  membership in a policy anyway. One membership policy everywhere is
  simpler.
- **`ash_events` for the record.** It stores each action's inputs and
  changed attributes verbatim, so every Version's HTML would be stored
  twice more, and it adds replay machinery the record does not need. It
  is pre-1.0. A create-only `Event` resource with one ordering sequence is
  the whole requirement.
- **OAuth 2.1 for Harnesses** (`ash_authentication_oauth2_server`,
  dynamic client registration, a consent screen). Click-to-connect is a
  better experience than pasting a key, at the cost of an OAuth server
  (pre-1.0) and consent UI. Revisit when key setup is the friction.
- **Harness Sessions.** Recording the MCP session per Event needs a patch
  to AshAi, which reads `Mcp-Session-Id` but does not pass it to action
  context. Revisit with OAuth or when sessions matter to the record.
- **Admin and member roles.** Temi's own team does not need them. Revisit
  when an Organization needs someone who can remove others but should not.
- **Email magic-link sign-in.** Needs an outbound email service; Google
  covers every `@usetemi.com` account. Revisit for self-hosters without
  Google Workspace.
- **Anonymous and public viewing.** Adds a second viewer kind, a
  read-only token grade, and a toggle. Revisit when an artifact must be
  shared outside its Organization.
- **The Rust CLI.** MCP covers Claude Code and Codex and the HTTP API
  covers everything else; a third client doubles the surface to keep in
  step.
- **Neon.** Chosen when artifacts were ephemeral; they are long-lived,
  and Fly Managed Postgres keeps compute and data on one platform with
  backups.
- **PgBouncer in front of Postgres.** MPG's pooler needs Transaction pool
  mode for Ecto, which drops named prepared statements and needs a
  second direct URL for migrations. One Machine already runs its own
  Ecto pool; skip the pooler and point `DATABASE_URL` at the cluster's
  direct host.
- **An opaque-origin sandbox or per-artifact subdomains instead of a
  content domain.** A null origin breaks pages that use storage; wildcard
  subdomains on the app domain are same-site with the session cookie.
- **A CRDT or a sync engine for State.** Not needed for a submit-based
  loop; Channels and row ops cover it.
