# Design

How Artifacts is built: architecture, Ash resources, authentication, the
page runtime, the MCP and HTTP interfaces, and deployment. `DOMAIN.md` owns
the language and the rules; this document names how each rule is carried
out and does not restate it. `README.md` is the short user-facing summary.

## Architecture

```
 Claude Code / Codex / Agent ── MCP + HTTP (bearer key) ──┐
                                                           ▼
 browser ── usetemi.art: sign-in, lists, settings, chrome ─► host (Phoenix + Ash) ── Postgres
    └─ iframe ── usetemicontent.art: page HTML + runtime.js ─►  │ Channels, PubSub, Presence
```

One Elixir release is the host. Ash resources hold the domain; Phoenix
serves the web app, the page origin, the channel socket, the MCP endpoint,
and the HTTP API from the same endpoint. Postgres is the only store. Every
artifact has one channel topic, `artifact:<id>`, which carries state ops,
presence, broadcast, and version events. There is no broker and no sync
service.

| Library | Role |
| --- | --- |
| `ash`, `ash_postgres` | Resources, actions, policies, Postgres data layer and migrations. |
| `ash_authentication`, `ash_authentication_phoenix` | Google sign-in for Users; API-key sign-in for Harnesses and Agents. |
| `ash_phoenix` | Forms and LiveView integration for the web app. |
| `ash_ai` | The MCP server: resource actions exposed as MCP tools. |
| `ash_json_api` | The HTTP API, generated from the same actions. |
| `usage_rules` | Syncs each dependency's usage rules into `server/AGENTS.md`. |

## Ash domains and resources

Two Ash domains, `Artifacts.Accounts` and `Artifacts.Publishing`.
Organization scoping is `belongs_to :organization` plus policies, not Ash
multitenancy (see [Rejected alternatives](#rejected-alternatives)).

### `Artifacts.Accounts`

| Resource | Holds | Notes |
| --- | --- | --- |
| `User` | email, name, `personal_organization_id` | Google strategy. `register_with_google` is an upsert on email. |
| `Token` | AshAuthentication session tokens | Generated by AshAuthentication. |
| `Organization` | name | |
| `Membership` | `user_id`, `organization_id` | Unique per pair. No role. |
| `Harness` | `user_id`, name, key hash, `expires_at`, `revoked_at` | The User's API-key resource: a Harness is one named key. |
| `Agent` | `organization_id`, name | Its own AshAuthentication resource with an API-key strategy. |
| `AgentKey` | `agent_id`, name, key hash, `expires_at`, `revoked_at` | An Agent's keys. |

### `Artifacts.Publishing`

| Resource | Holds | Notes |
| --- | --- | --- |
| `Artifact` | 22-char URL-safe random id, `organization_id`, title, `current_version`, `archived_at` | The aggregate root; every content action runs on it. |
| `Version` | `artifact_id`, number, html, actor | Create only. Primary key `(artifact_id, number)`. |
| `StateEntry` | `artifact_id`, path, value, actor, `updated_at` | One row per leaf path; see [State](#state). |
| `Submission` | `bigserial` id, `artifact_id`, version, state snapshot, payload, actor | Create only. The id is the wait cursor. |
| `Event` | `bigserial` id, `artifact_id`, kind, actor, data, `inserted_at` | Create only. The id is the History order. |

Actor columns are the same on `Version`, `StateEntry`, `Submission`, and
`Event`: nullable `user_id`, `harness_id`, and `agent_id`. A User acting
through the browser sets `user_id`; a Harness sets `user_id` and
`harness_id`; an Agent sets `agent_id`. A check constraint requires exactly
one of `user_id` and `agent_id`, and `harness_id` only with `user_id`.

`Version`, `Submission`, and `Event` have no update or destroy actions and
their foreign keys restrict deletion, so no path in the application or in
SQL through the app's role drops a record. `Artifact` has no destroy action.

## Authentication and actors

Three credentials, two actor types. Policies only ever see a `User` or an
`Agent`.

| Credential | Presented by | Resolves to |
| --- | --- | --- |
| Session cookie from Google sign-in | Browser on usetemi.art | `User` |
| Harness key (`Authorization: Bearer art_h_…`) | Claude Code or Codex over MCP or HTTP | `User`, with the `Harness` in `user.__metadata__.api_key` |
| Agent key (`Authorization: Bearer art_a_…`) | A coworker agent over MCP or HTTP | `Agent` |

Keys are generated by AshAuthentication's `GenerateApiKey` change with a
kind-specific prefix, stored as a hash, and shown once at creation. The
bearer plug routes by prefix to the User or Agent API-key strategy. A
plug after it copies the Harness id into the Ash context so actions can
record it; that is the only place the Harness enters the actor columns.

**Sign-up.** `register_with_google` rejects an email that is unverified
or whose domain is not in `SIGNUP_EMAIL_DOMAINS` (empty means any), so no
User row is written. On success an `after_action` hook, in the same
transaction, creates the Personal Organization and its Membership and
sets `personal_organization_id` when the User has none, so a repeat
sign-in changes nothing.

**Membership invariant.** `Membership.destroy` (remove or leave) locks the
organization row and refuses when it is the last Membership. Adding a
member looks up an existing User by email and fails when there is none.

**Policies.** One rule covers every `Artifacts.Publishing` action and the
Organization-scoped Accounts actions: a `User` passes when
`exists(organization.memberships, user_id == ^actor(:id))`, an `Agent`
when `organization_id == ^actor(:organization_id)`. `Harness` actions
pass only for their own User. Actions that manage access (Membership
create and destroy, Agent create, Harness and AgentKey create and revoke)
also `forbid_if AshAuthentication.Checks.UsingApiKey` and forbid Agent
actors, so only a browser-signed-in User manages access. Reads by id load the record and filter by
the rule, so a non-member gets not-found, never forbidden.

## Content changes

Every content change is one action on `Artifact` that writes the change
and its `Event` in one transaction and then broadcasts on
`artifact:<id>`. The `Event.data` holds a pointer, not a copy:

| Action | Writes | `Event.kind` | `Event.data` |
| --- | --- | --- | --- |
| `publish` | a `Version`, bumps `current_version` | `version_published` | `{number}` |
| `change_state` | `StateEntry` upserts and deletes | `state_changed` | the ops list |
| `submit` | a `Submission` | `submission_made` | `{submission_id}` |

`create` is `publish` on a new Artifact: it inserts the Artifact with
`current_version` 0 in the target Organization (named, else the actor's
Personal Organization; an Agent's own), then publishes version 1.

`publish` takes an optional `if_version`; it locks the Artifact row and
returns a conflict error when `current_version` differs. Self-Publish
always sends it.

`rename`, `archive`, and `unarchive` update the Artifact and write no
Event. Every content action validates `archived_at` is nil and fails
with an `archived` error otherwise.

Caps, each a validation with a visible error: 16 MiB per Version, 256 KiB
per state value, 10,000 state rows and 10,000 submissions per Artifact.

### State

State is a JSON object assembled from rows, one row per leaf at a dotted
path. `set("a.b", 1)` upserts `a.b`; setting a path replaces every row at
or below it with the leaves of the new value, so the document never holds
both `a` and `a.b`. `delete("a")` removes `a` and `a.*`. Arrays are one
leaf; to edit elements independently, key them (`items.<id>`). `null`
means absence. Ops in one `change_state` apply in one transaction; across
changes the last write to a path wins.

### History

`Artifact.history` reads the artifact's Events in id order, paged by an
`after` cursor, and loads what each points at: the Version (with or
without HTML, by flag), the Submission, or the ops inline. Presence and
broadcast never reach the database.

## Page origin and runtime

usetemi.art serves the web app and the chrome; usetemicontent.art serves
page HTML and nothing else. The endpoint routes by host: the content host
answers only the page route and the channel socket, sets no cookies, and
reads none.

**Page token.** The chrome LiveView mints a `Phoenix.Token` carrying the
artifact id and the viewing actor, valid for 10 minutes. The iframe's
`src` is `https://usetemicontent.art/a/<id>/page?t=<token>`. The page
route verifies the token, re-checks the actor against the policy, and
returns the current Version's HTML with the runtime `<script>` injected
right after `<head>` and the token in its config. Stored HTML is never
modified. The token's 10-minute lifetime bounds any leak; responses also
set `Referrer-Policy: no-referrer` and `Cache-Control: no-store`, and the
`t` parameter is filtered from request logs. Responses carry a CSP
allowing scripts from this origin and the common CDNs, connections to the
socket host only, and images from anywhere. The iframe is `sandbox`ed with scripts, same-origin, forms,
modals, popups, and downloads allowed, but not top navigation, so a page
cannot navigate the chrome's tab.

An archived Artifact's chrome shows its title and archive status with an
Unarchive control and no iframe; its Versions, State, and History are
read through MCP and the HTTP API.

**Socket.** The runtime connects to the socket with the token as a
connect param; the socket assigns the actor, and joining
`artifact:<id>` requires the token's artifact id. After expiry, the
runtime asks the chrome for a fresh token over `postMessage` (checked
against the app origin) before reconnecting. A new Version makes the
chrome reload the iframe with a fresh token; State survives because it is
in Postgres.

### Channel protocol

The join reply carries `{version, state}` (the flat map of rows); Phoenix
Presence sends the list right after. An archived artifact refuses the
join.

| Direction | Event | Payload |
| --- | --- | --- |
| page → host | `state:ops` | `[{op: "set", path, value} \| {op: "delete", path}]`; reply after commit |
| host → pages | `state:ops` | the same ops plus `by`, to every subscriber, the writer included |
| page → host | `presence:update` | meta to merge into this viewer's presence |
| page → host | `broadcast` | `{topic, data}`; re-emitted to the other pages with `from` |
| page → host | `submit` | `{payload}`; reply `{id}` |
| page → host | `publish` | `{html, if_version}`; reply `{version}` or `{error: "conflict"}` |
| host → pages | `version` | `{version, by}` on every publish |

Channel writes call the same `Artifact` actions as MCP and HTTP, with the
token's actor.

### Page API

`runtime.js` defines `window.artifact`, available synchronously; its
connection opens asynchronously, so pages await `artifact.ready`.

```js
await artifact.ready;
artifact.id; artifact.version;
artifact.viewer;                       // {id, name}: the signed-in User

artifact.state.get("cards.c1");
await artifact.state.set("cards.c1.column", "done");
await artifact.state.delete("cards.c1");
const stop = artifact.state.subscribe((state) => render(state));

artifact.presence.track({cursor: [120, 44]});
artifact.presence.onChange((viewers) => renderPeers(viewers));

artifact.broadcast("pointer", {x, y});
artifact.on("pointer", (data, from) => flash(data, from));

await artifact.submit({choice: "B"});
await artifact.publish(html);          // rejects {code: "conflict"}
```

`state.set` applies locally at once and resolves on commit.
`subscribe` fires once after sync and then per change, coalesced per
animation frame. Writes reject with `{code: "archived"}` once archived and
`{code: "unavailable"}` while disconnected. The runtime never touches the
DOM. The chrome's Submit button calls `submit` with no payload, so every
page can be handed back.

## Agent interfaces

### MCP

`AshAi` exposes the tools below at `https://usetemi.art/mcp` (streamable
HTTP), behind the bearer plug. Each tool is an `Artifact` or
`Organization` action, so MCP enforces the same policies as the web.

| Tool | Action |
| --- | --- |
| `list_organizations` | Organizations the actor can act in. |
| `list_artifacts` | Open artifacts in one Organization. |
| `get_artifact` | Metadata and, optionally, a Version's HTML. |
| `publish_artifact` | Create, or publish a new Version (`if_version`). |
| `get_state` / `change_state` | Reduced State; apply ops. |
| `submit` | Submit with an optional payload. |
| `wait` | Submissions after `since`; see below. |
| `history` | One page of the History after a cursor. |
| `rename_artifact` / `archive_artifact` / `unarchive_artifact` | Metadata and closeout. |

**`wait`** is a generic action: `wait(artifact_id, since, timeout)`. It
subscribes to the artifact's topic, reads Submissions with `id > since`,
and returns them at once or blocks until one arrives or `timeout`
passes, then returns an empty list. `since` omitted means "after the
latest submission now". `timeout` defaults to 45 seconds and is capped at
50, under Codex's 60-second default MCP tool timeout; Claude Code's limit
is set after testing it. The agent calls again with the last id it saw.

Connecting a harness:

```
claude mcp add --transport http artifacts https://usetemi.art/mcp \
  --header "Authorization: Bearer art_h_…"
```

```toml
# ~/.codex/config.toml
[mcp_servers.artifacts]
url = "https://usetemi.art/mcp"
bearer_token_env_var = "ARTIFACTS_KEY"
```

### HTTP API

`AshJsonApi` routes under `/api` expose the same actions for anything
that is not an MCP client, authenticated by the same bearer keys. Raw
Version HTML is also served at `GET /api/artifacts/:id/versions/:n.html`
for fetching a page as a file.

### Skill

`skills/artifacts/SKILL.md` teaches the loop over MCP: when a page beats
text, how to write one against `window.artifact`, `publish_artifact`,
`wait` in a loop, act on the Submission, republish, and read `history`.

## Web app

LiveView on usetemi.art, behind Google sign-in:

- **Artifacts**: the open Artifacts of the selected Organization, with an
  Organization switcher; archived ones behind a filter.
- **Artifact page** (`/a/:id`): the chrome (title, Version, Presence,
  Submit, rename, archive) around the page iframe.
- **Settings**: create an Organization; add a member by email, remove a
  member, leave; create an Agent and issue or revoke its keys; create or
  revoke your own Harnesses. A new key is shown once.

## Deployment

**Fly.io** (`deploy/fly/fly.toml`): one Machine that stops when nothing
is connected and starts on the next request, serving both hostnames, in the same region as
a Fly Managed Postgres cluster attached with `fly mpg attach` as
`DATABASE_URL`. Migrations run as the `release_command`. Both hostnames
get certificates with `fly certs add`. MPG's backups hold the record. An open page's socket or a running `wait`
keeps the Machine up; after a stop, pages reconnect and rejoin with a
fresh snapshot, and `wait` resumes from its cursor.

**Docker Compose** (`deploy/docker-compose.yml`): the image plus a
Postgres container; local development, tests, and self-hosting. Two
hostnames are needed locally too; `localhost` and `127.0.0.1` serve as
app and content hosts.

Configuration is environment variables: `DATABASE_URL`,
`SECRET_KEY_BASE`, `TOKEN_SIGNING_SECRET`, `APP_HOST`, `CONTENT_HOST`,
`GOOGLE_CLIENT_ID`, `GOOGLE_CLIENT_SECRET`, `SIGNUP_EMAIL_DOMAINS`,
`PORT`.

## Limitations

- **Content origin is shared across artifacts.** Every page runs on one
  content origin, so pages share its localStorage and can read what
  another page stored there. Per-artifact subdomains would separate them.
- **A page can exfiltrate what its viewer can see of its own artifact.**
  The CSP limits connections but allows images from anywhere.
- **Single node.** PubSub fan-out is in-process; a second node needs a
  shared PubSub adapter.
- **Nothing is deleted.** The database only grows.

## Rejected alternatives

- **Ash multitenancy for Organizations.** Artifacts are opened by
  unguessable id before their Organization is known (links, MCP calls
  that name none), so every such read would bypass the tenant and re-check
  membership in a policy anyway. One membership policy everywhere is
  simpler.
- **`ash_events` for the record.** It stores each action's inputs and
  changed attributes verbatim, so every Version's HTML would be stored
  twice more, and it adds replay machinery the record does not need. It
  is pre-1.0. A create-only `Event` resource with one ordering sequence is
  the whole requirement.
- **OAuth 2.1 for Harnesses** (`ash_authentication_oauth2_server`,
  dynamic client registration, a consent screen). Click-to-connect is a
  better experience than pasting a key, at the cost of an OAuth server
  (pre-1.0) and consent UI. Revisit when key setup is the friction.
- **Harness Sessions.** Recording the MCP session per Event needs a patch
  to AshAi, which reads `Mcp-Session-Id` but does not pass it to action
  context. Revisit with OAuth or when sessions matter to the record.
- **Admin and member roles.** Temi's own team does not need them. Revisit
  when an Organization needs someone who can remove others but should not.
- **Email magic-link sign-in.** Needs an outbound email service; Google
  covers every `@usetemi.com` account. Revisit for self-hosters without
  Google Workspace.
- **Anonymous and public viewing.** Adds a second viewer kind, a
  read-only token grade, and a toggle. Revisit when an artifact must be
  shared outside its Organization.
- **The Rust CLI.** MCP covers Claude Code and Codex and the HTTP API
  covers everything else; a third client doubles the surface to keep in
  step.
- **Neon.** Chosen when artifacts were ephemeral; they are long-lived,
  and Fly Managed Postgres keeps compute and data on one platform with
  backups.
- **An opaque-origin sandbox or per-artifact subdomains instead of a
  content domain.** A null origin breaks pages that use storage; wildcard
  subdomains on the app domain are same-site with the session cookie.
- **A CRDT or a sync engine for State.** Not needed for a submit-based
  loop; Channels and row ops cover it.
